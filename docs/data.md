## 처리 메모

- Shape-from-Shading DEM은 기본 다운로드에 들지 않는다: `uv run python -m lunar_margin.pipeline.fetch --sfs` (약 400 MB). GeoTIFF(32비트 실수, deflate, 부동소수점 예측자)는 `pipeline/geotiff.py`가 읽는다.
- 60°S까지의 240 m DEM도 기본 다운로드에 들지 않는다: `uv run python -m lunar_margin.pipeline.fetch --wide` (약 240 MB). 받은 뒤 `uv run python -m lunar_margin.pipeline.overlay_tiles --wide-only`로 `normal-wide` 타일만 굽는다 (약 20초, 13 MB).
- 다운로드는 크기와 sha256을 `manifest.json`에 기록하고, 다음 실행에서 파일이 달라졌으면 다시 받는다.
- DEM 이미지는 PDS3 라벨(`.lbl`)로 해석한다. 32-bit little-endian float(`PC_REAL`), 값 단위 km.
- 격자 방향은 Malapert 산(약 +5 km)과 Shoemaker·Haworth·Faustini 크레이터 바닥(약 -3.4~-4 km)으로 검증했다 (`api/tests/engine/test_dem_real.py`).

## 탐색 중 수평선 자동 저장

후보 탐색은 전체 사전 계산 테이블을 우선 사용한다. 테이블에 없는 지점은
`$DATA_DIR/horizon-cache/height-3m-<설정 식별자>.sqlite3`처럼 높이별 파일에 저장한다.
관측 높이, DEM/라벨 파일의 식별 정보, 방위각 간격, 최대 탐색 거리가 같은 경우 날짜·기간·필터·ROI가
달라도 같은 지점의 수평선을 재사용한다. 0 m와 3 m, coarse 2°와 fine 1° 계산은 섞이지 않는다.
날짜별 일괄 탐색도 전체 테이블이 없으면 같은 지점별 캐시를 공유하며 순서대로 계산한다.

- 64개 지점 묶음이 완료될 때마다 원자적으로 저장한다. 중단된 탐색의 이전 완료 묶음은 다음 실행에서 재사용한다.
- 수평선 값은 float64 그대로 보존한다. 최초 계산과 재사용 사이에 추가 양자화 오차를 만들지 않는다.
- `run.log`의 `수평선 캐시: 재사용 N, 새로 저장 M`으로 실제 재사용 여부를 확인한다.
- 처음 만나는 지점은 여전히 계산 시간이 필요하다. 저장 전에 실행된 과거 탐색의 수평선 중간값은 복구하지 못한다.
- 캐시는 개별 탐색 결과 폴더 밖에 있으므로 결과 재시도 시에도 유지된다. DATA_DIR을 보존해야 다음 탐색에서 사용할 수 있다.
- SQLite와 그 WAL 파일을 실행 중 수동 삭제하거나 복사하지 않는다. 수평선 알고리즘/저장 표현이 바뀌면 CACHE_VERSION을 올린다.
